日期：2026-10-20。状态：**供 review，未部署；新版客户端导入未实测**。

## 本版映射

- “删掉这项”“不要刚加的”“撤回加购”先刷新房间，以最新清单版本和唯一行 ID 调用 `update_order_draft(operation="remove")`；“少一份”“改成 N 份”用 `set_quantity` 指定最终数量，减到零改用 `remove`。歧义时询问，不猜清单行。
- 个人行只由所属玩家修改；房主也不能删除 B 的个人行。共享行只由房主修改。结账固定整份清单，不能绕过权限只挑一方商品建单。
- PREPARED、HANDED_OFF、QUOTED、SUBMITTING、UNKNOWN、ORDER_CREATED 各有不同的撤回边界。清单删除不取消麦当劳官方订单；写操作结果未知先核对，不用新事件 ID 盲目重放。
- 补明撤回本人准备、拒绝尚未采纳的推荐、锁店后改店的处理。查看报价需刷新；`AGENT_REPORTED` 不等于未调用官方核价。辩论正文压在工具 200 字上限之下。

## 尚未覆盖或仍需验证

- **真实订单取消与退款**：当前 `remove`、`cancel_checkout`、`cancel_battle`、`close_room` 都不能取消麦当劳已创建的订单。Skill 尚未定义官方 `cancel-order` 的身份核验、结果确认与退款交接；用户提出这类请求时不能把删除草稿当成已取消订单。这需要另一个明确的官方订单取消流程。
- **“只看报价”的读取可靠性**：最新定向测试 1/2 次未刷新状态，可能展示旧报价。服务端版本检查能阻止旧版本写入，不能纠正 Agent 已说出的旧价格；客户端真实会话需重点复测。
- **客户端实际安装**：0.3.4 ZIP 与 bundle 完成静态校验，豆包 Work / WorkBuddy 手机端是否加载新版 Skill、保留两个 MCP 连接，仍须在客户端确认。真实官方取消、支付与外卖不在本次测试范围。
